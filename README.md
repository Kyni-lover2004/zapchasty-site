# PartStack — серверный каталог и админка

Сайт теперь получает товары из PostgreSQL. Для работы нужен Django-сервер; `python3 -m http.server` больше не подходит.

Локально: `source .local/env`, затем `.venv/bin/python backend/manage.py runserver 127.0.0.1:8000 --noreload`. Сайт: http://127.0.0.1:8000/, админка: http://127.0.0.1:8000/admin/.

Инструкция для Ubuntu/Debian и сотрудников: [deploy/README.md](deploy/README.md). Локальные данные входа: `.local/admin-access.txt`.

## Что уже работает

- Поиск по модели, названию и артикулу (например, `iPhone 11` или `DSP-IP11`).
- Категории и фильтры: бренд, наличие, цена, сортировка.
- Карточка товара с характеристиками и совместимостью.
- Корзина с изменением количества, сохраняется в `localStorage`.
- Оформление через Telegram @rznmastershop62: ссылка открывает чат с черновиком из корзины (названия, варианты, артикулы, количество и сумма). Покупатель отправляет сообщение сам. VK пока не подключён.
- Полей контактов, согласия, создания заказа и истории заказов нет.

## Что заменить перед публикацией

- Админка → «Настройки магазина»: проверьте ссылки на VK и Telegram, адрес, телефон и график.
- Админка `/admin/` → «Товары»: цены, остатки, совместимость и фото. `data.js` — архив исходного демо, не рабочий каталог.
- `assets/css/style.css`: палитра в блоке `:root` (серый, голубой, белый).

## Структура

```
index.html                 — каркас, шапка, подвал, мобильная навигация
assets/css/style.css       — оформление и адаптив
assets/js/data.js          — категории, товары, контакты, соцсети
assets/js/app.js           — поиск, фильтры, корзина, заказы
assets/img/*.svg           — иллюстрации категорий и иконка сайта
```

## Доработки покупательского сценария

- Отдельный подбор по бренду и точной совместимости модели; параметр `model` сохраняется в адресе.
- Подсказки поиска по названию и артикулу; стрелки для перехода, Escape для закрытия.
- Избранное сохраняется в браузере.
- Снимаемые фильтры категории, бренда, модели, наличия и цены. Перепутанные границы цены автоматически меняются местами.
- Видимое количество в корзине на карточках; исправлено перекрытие кнопок ссылкой карточки.
- Контактные данные и история прежней формы удаляются из браузерного хранилища при открытии сайта.
- Сохранённое количество ограничивается складским остатком; недоступные и повреждённые позиции исключаются.

Прежний клиентский прототип заменён серверным каталогом. Вход сотрудников и каталог работают через Django/PostgreSQL. Заказы оформляются в Telegram.

Проверка логики: `node --test tests/catalog.test.cjs`. Проверены поиск, совместимость, фильтрация, сортировка, восстановление корзины удаление данных прежней формы и безопасную обработку ссылок соцсетей. В браузере проверены покупательские действия и мобильный каталог на ширине 390 px.

Если клиент Telegram не подставил сообщение, доступна кнопка копирования и просмотр полного текста. Для длинных списков используется обычная ссылка на чат с инструкцией скопировать состав, без обрезания товаров. При пустой корзине открывается чат без черновика. Переход в Telegram не очищает корзину.
